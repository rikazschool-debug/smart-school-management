# Communication & circulars rules (enforced in SQL; this UI mirrors them)
- Communication: one service for every role — conversations (kind family|direct|group) + conversation_members (membership periods via left_at, visible_from for history policy) + messages (per-conversation seq, unique sender+client_id for idempotent retries). All writes go through RPCs (send_message, start_family_conversation, start_direct_conversation, create_group, add/remove_group_member, …); authenticated has SELECT only. Read access = active member row + conv_access_ok (current school/org membership; for family chats a still-verified guardian link). Sending additionally needs conv_send_block() = null (relation still valid via _family_ok, group active/not expired, post policy). Managers see group metadata but never private message content; the only exceptional read is report_detail on a reported message, which is audited in comm_audit.
- Section groups (group_type='class', dedupe 'class:<section>:<year>') are the teaching channel: one per section+year, synced only by sync_class_group from triggers (enrollments, assignments, student_guardians/guardians, memberships, years). Members = enrolled students + live assigned teachers + verified guardians + active principal (always moderator); conversation_members.reasons keeps every reason. Manual edits only by principal/owner via class_group_* RPCs, stored in conv_member_overrides (added/removed/role + reason) which resync respects; manual adds are school staff only and need a reason. Post policy all|moderators|staff_guardians set only by principal/owner. Old subject groups ('course') are frozen read-only archives (sync_course_group is a no-op); class_group_migrate/rollback log counts in class_group_runs. Tests: scripts/class-groups-e2e.ts.
- Students: subject groups + teacher-started private chats only; administrative circulars exclude students (_circular_audience, can_read_circular). Group members are removed/added only by owner/principal (_can_create_group), never by moderators.
- Circulars: scope school|branches|org (wider than school = org owner only, never platform admin); audience resolved at publish into circular_recipients with the recipient's branch (later joiners never recipients; read lost when that membership ends); revise_circular snapshots versions; ack_circular is separate from open_circular.
- Message/circular attachments reuse the files service: create_message_file makes a 'message_pending' row, the client uploads, and send_message verifies the storage object exists before linking it (source_type='message'). Stale pending files are removed by the uploader's client (cleanupStalePending).
- Teacher↔student private chats are kind='student' (dedupe 'student:<student>:<teacher>'), started only by the teacher via start_student_conversation and gated by _student_ok; guardians are never added — student privacy and no student↔student chats.
- Report review rights come from comm_settings.report_reviewer_roles via _report_reviewer (org owner only for cross-branch groups); never widen to all managers or platform admins.
- Manual groups: created/filled only by org owner (any branch/cross-branch), principal (own school) or an owner-granted groups.create holder, via _can_create_group (perm_allows); derived class groups are untouched.
- Server test: scripts/comm-e2e.ts (see scripts/AGENTS.md).
- Hub circulars (orgWide for the org owner) list and target the whole org; the last visited school is only the default home school. Groups come from every selected branch, grouped by branch.
- Identity privacy in class/course/section groups: _cg_sender_visible decides per viewer (self, school staff member of the group or manager, staff sender, own verified child). Thread reads only via conv_messages (generic «طالب»/«ولي أمر», null sender_id); messages/conversation_members/files RLS hide masked rows, so ids never reach the client; conversation_people/class_group_members/search_messages apply the same filter. Reveal needs the server-side active capacity (user_active_context via set_active_context, never trusted from the client without a matching membership) to be staff for that school + live group membership with a staff reason/moderator or a principal override; messages.sent_as (trigger) fixes the capacity per message. Masked viewers get live updates only via topic-only live_signals 'msg'. Tests: scripts/cg-privacy-e2e.ts, cg-privacy-journey.py, cg-live-journey.py, cg-switch-journey.py.
- Chat settings (cs_*, perm section chat_settings, org scope): owner or explicit grant via _cs_ok; never reads conversations. Saved replies (cs_my_replies: active + role match + conv_send_block null) are inserted as editable plain text, never auto-sent. Auto replies only in private chats (direct/family/student) via trigger _cs_auto_trg: off by default, activated_at blocks retroactive runs, cs_auto_runs unique(rule,trigger msg) + deterministic client_id stop duplicates, never answers kind='auto', sender shown as rule label (sender_id hidden). Voice: create_voice_file checks org limits; _msg_file_link_trg checks the stored object's real size/type at send. Gallery: conv_files with conv_messages visibility (safe names when masked). Tests: scripts/cs-e2e.ts.

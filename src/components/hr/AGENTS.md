# HR rules
- Every HR page starts with HrPageTop (navigation.tsx: breadcrumb, title band, section tiles) and employee cards share presentation modules; routes keep data and actions so layout changes never alter authorization.
- Log: docs/hr/execution-log.md (update per package).
- HR attendance (hr_att_*): RPC-only; raw punches append-only and separate from computed hr_att_days; closed days change only after dated reopen; devices via signed /api/public/hr/attendance → service-only _hr_att_ingest; money effect only via payroll. Tests: hr-att-e2e, hra-journey.
- HR pay (hr_decisions/hr_advances/hr_pay_*): RPC-only; dated hr_pay_policies, unset = held. Tests: hr-pay-e2e, hrp-journey.
- HR extensions: owner switch (hr_ext_settings); recruitment hr_rc_*, convert once. Tests: hr-recruit-e2e, hrr-journey.
- Mobile punch: hr_att_self_punch always needs a fresh (≤60 s), accurate reading inside the school site (hr_att_sites) of a live assignment; only school/distance/accuracy are stored. Asset custody (hr_assets/hr_asset_custodies): one open custody per asset (unique index), never touches money. Tests: hr-loc-assets-e2e, hla-journey.
- Principals get no HR section by default (no _perm_base/template grant); access only by explicit grant.
- Personal file access: hr_employees.self_access is switched only via hr_self_access_set (HR edit perm, never by the person; owner excepted); linking/import/relink always leaves it off; every self path (_hr_*_self, hr_my_*, payslips, docs) requires it. Tests: hr-self-e2e, hse-journey.
- HR reports: only hr_report_catalog/hr_report (server catalog _hr_rep_meta); rows, masking and totals from the server; view = module view, print = hr_reports.print, export = module export; print/export logged. Tests: hr-reports-e2e, hr-pay-e2e.
- Addresses (hr_employee_addresses): only hr_address_get/save; full address needs sensitive (or own file), others see city only; logs store changed field names, never values. Hourly permissions (hr_perm_requests, five kinds): employee → direct manager → HR via hr_perm_*; server computes minutes and refuses overlaps/end ≤ start; no money effect. Opening balances (hr_open_batches): server preview → draft with source rows/total → approved by a different person only when totals match; posts append-only opening moves keyed per employee so re-import skips. Tests: hr-p10-e2e, hp10-journey.
- Job categories (hr_job_categories, RPC hr_cat_*) live on hr_assignments.category_id; they describe the job only and never grant roles/permissions. HR save RPCs are thin wrappers over _hr_*_save_base.
- New employee + login from HR: createHrEmployeeLogin (accounts.functions.ts) makes a locked auth user recorded in service-only hr_login_pending, then hr_employee_create_login (caller's perms; roles from _hr_login_roles, owner any staff role, others non-leadership only) writes file+membership(+teacher) in one transaction; unlock last; retry reuses pending; ID/phone conflicts stop, never merge. Test: hr-login-e2e.
- Employee data fields: one definition in src/lib/hr-fields.ts (34-column template order, groups, sensitivity, validation) used by the form, file view and Excel import; extra data in hr_employee_profile via hr_employee_profile_get/save only (mode fill never overwrites or clears); manager matched by employee number. Groups (HR_GROUPS) = the approved «إضافة موظف» tabs 1–6, then account (7) and review (8, required-field list + hr_employee_dupcheck for employee no./ID); fixed lists in HR_OPTIONS (old free-text values stay selectable); licence and intermediary fields are frozen, not hidden; document dates have a Hijri (Umm al-Qura via Intl)/Gregorian picker (doc-date-picker.tsx) that only fills the same text + calendar fields. Tests: src/lib/hr-fields.test.ts, scripts/hrtabs-journey.py, scripts/hrx-journey.py (hrx-browser-fixture); hr-import-journey.py is superseded.
- Import with logins (optional, needs sensitive): per-row plan from hr_login_plan (create / link existing staff account after explicit confirmation via hr_employee_link_login, keeps its roles / review on missing or conflicting ID/phone); role = row pick or owner-only title→role table hr_title_roles (hr_title_role_set); creation via createHrEmployeeLogin per row (same server role/school limits, retry reuses pending, re-upload = existing file). Test: scripts/hrl-journey.py (hrx-browser-fixture).
- B13 roles: templates «مساعد إداري» (school: school_schedule.view, attendance.view/record → full published timetable via can_view_slot + schedule_slot_subjects, roster via att_roster, manual_attendance) and «مدير إدارة الموارد البشرية» (org scope HR). Central administration = staff membership and hr_assignments with school NULL, only for the HR director (hr_login_central_roles, owner-only). Existing guardian account → hr_employee_link_guardian after _hr_plan_guardian ID+phone match (adds staff role, guardian links untouched). Named owner manager = manager_owner → owner's own HR file (_hr_owner_emp); trigger blocks self-manager. Tests: scripts/b13-e2e.ts (needs timetable-e2e --keep), b13-browser-fixture.ts.
- Direct manager per import row (B14): ManagerPick (src/components/hr/manager-pick.tsx) over active org employees, owner accounts (hr_org_owners → manager_owner) and rows of the same batch; Excel number only preselects; batch managers linked in a second pass after their file exists. Server trigger _hr_mgr_self_trg refuses self, other org, inactive and chain loops. Bilingual labels/English hints: src/lib/hr-bilingual.ts (display only, never saved). Tests: scripts/b14-e2e.ts, b14-journey.py (hrx-browser-fixture), src/lib/hr-bilingual.test.ts.
- Customer service agent: template cs_agent «مسؤول خدمة العملاء» (perm customer_service.handle, owner-granted via _hr_login_roles, title mapping allowed); menu «خدمة العملاء» = support page; ticket access stays support_* (assignee only). Central administration rows in Excel import use CENTRAL (owner only, HR director only; hr_employee_link_guardian accepts no school). Test: scripts/cs-agent-e2e.ts.
- Employee ID/passport/licence extras (id_type none disables ID+version and blocks login creation; id_version text; passport expiry ≥ issue; licence fields only when has_licence): hr_employee_profile columns via hr_employee_profile_save; ID type/version and passport issue data are sensitive. Test: scripts/hrtabs-journey.py (hrx-browser-fixture); hrid-journey.py predates the tabs (add-screen steps superseded).
- Legacy ZKTeco path (kept for existing devices/history; not used by contract v1): devices push plain HTTP, the site is HTTPS-only, so bridge/adms-bridge.mjs (no deps, runs on a PC/VPS) forwards ATTLOG rows only, signed, with `sn` to /api/public/hr/attendance → service-only _hr_att_ingest2 (serial must match hr_att_devices.serial_no). PIN → hr_att_device_pins, else employee_no, same school only; others go to hr_att_unmatched (review: hr_att_pin_link moves rows, hr_att_unmatched_dismiss with reason). ref = SN:PIN:time so resends never duplicate. Key rotation hr_att_device_rotate. Test: scripts/adms-e2e.ts (needs dev server).
- Principal staff directory: read-only school_staff_directory (is_school_principal) over live hr_assignments; returns only name/number/title/kind/category/branch/account status — never salary, ID, documents or bank. UI: src/components/staff-directory.tsx on /app/teachers. Test: staff-dir-e2e.
- Employee file view + print: one layout from src/lib/hr-sheet.ts (buildSheet = «إضافة موظف» groups 1–6 + «الحساب والصلاحيات»), used by EmployeeSheetView and the print preview (sheetHtml, iframe, page per employee). Print data only from hr_employee_print (view + new hr_employees.print per employee, branch scope, same masking as hr_employee_get/profile_get, out-of-scope counted as refused, each print logged in hr_events); account rows from _hr_emp_account (roles/templates, never secrets). Tests: src/lib/hr-sheet.test.ts, scripts/hr-print-e2e.ts.
- Bulk employee actions: hr_employee_bulk (transfer/suspend/activate/archive/restore, reason required, per-employee result, logged); «delete» = status archived (file kept, assignments ended), never a row delete. Login follows HR: trigger _hr_login_follow_trg moves the user's staff memberships to the school of a live primary assignment (duplicate role there → old one deactivated), logged in access_audit; future-dated transfers move when edited after start. Employee-guardian children via hr_employee_children (same login or ID in org). Test: scripts/hr-bulk-e2e.ts.
- ADMS Bridge contract v1: the bridge owns orgs/sites/devices; Rikaz keeps a linked copy (adms_*) via signed health/sync (src/lib/adms/sync.ts, page+cursor in one transaction) and receives events only at /api/integrations/adms/v1/events (src/lib/adms/receiver.ts → service-only _adms_ingest: nonce + raw rows in one transaction before the per-event ACK). PIN matching explicit per bridge device; processing into hr_att_punches is a separate owner-switched step. SQL lives in supabase/pending/adms_v1.sql until approved. Tests: src/lib/adms/adms.test.ts, scripts/adms-v1-isolated.ts (local Postgres, optional real bridge worker). Details: docs/integrations/adms-v1.md.

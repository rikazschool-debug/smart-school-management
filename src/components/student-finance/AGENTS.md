# Student finance UI
- All amounts come from sf_* RPC results and use existing RTL primitives; edits invalidate the shared student-finance query prefix.
- Setup is owner-only, ordinary financial actions use independent server-returned caps, and family presentation omits all write controls.
- Fee setup lives as the owner-only «الرسوم الدراسية» tab of the academic page; the student finance tab sits inside the existing student panel and the finance page lists accounts from sf_report — no duplicate sections.
- Family «الحسابات المالية»/«سندات القبض» (student-finance/family-finance.tsx) read only sf_family/sf_student_receipts; family totals are sums of server balances, never local recomputation.
- Owner home has one «المالية والمحاسبة» card opening /app/accounting (FinancePortal cards, no side menu); «العهد والمشتريات» (/app/procurement) and «حسابات الطلاب» (/app/finance) are separate sections, each with only its own side menu; student-account sub-pages are SF_GROUPS views (?v=) sharing one school (?b=) and year (?y=) selector — add new finance pages there, never as separate menu sections. Family/home/child finance all read sf_family (one source).
- Bank-transfer proof is optional: after sf_collect, sf_transfer_attach creates a files row (source sf_transfer, readable via _sf_ok view) then the browser uploads; listed by sf_transfer_files. A failed upload never undoes the payment. Test: scripts/sf-transfer-e2e.ts.
- Receipts print/PDF through receiptHtml (finance-tools.tsx: letterhead, student/payment sections, items table, totals) via exportPagePdf/printPage — one design for every screen; the payer on a collection is set server-side to the recording employee (trigger sf_collect_payer), never typed.
- Finance list search goes through useStudentSearch (search.ts → sf_search_index): student name/ID/number + guardian name/ID/mobile, finance-view only.
- Applied discounts / transport accounts / adjustments pages (pages.tsx) and the reports catalog (reports.tsx) read only sf_discount_list, sf_transport_accounts, sf_adjustments, sf_obligation_lines, sf_collection_lines (all _sf_guard view); reports are derived client-side from these lines — never report-only balances. Reversed collections are excluded from totals; credit use is never counted as cash. Branch home HomeFinance shows sf_dashboard only when sf_can(view). Test: scripts/sf-security-e2e.ts (KEEP=1 keeps the owner session for a browser check; delete it after).
- Granted staff (perm student_finance.view) open /app/finance for their active branch only; SF_OWNER_VIEWS (carry/pay links/fee creation) stay owner-only. sf_report guards view.
- Live refresh: sf_collections/obligations/carries/receipts signal topic `sf` (school staff + the student's guardians); live-signals.ts refetches every SF_KEY query. Excel exports turn «ر.س» amounts into numeric cells (moneyValue in export.ts).
- Finance tables use useRowSelect (row-select.tsx): exports take the ticked rows when any, else all shown; the printable statement uses statementHtml in the receipt style.
- Receipts are year-scoped server-side (sf_receipts _year: fees of that year or carried items after the carry, one row per receipt, with fee_years/collection_year); «كل الأعوام» passes null.
- Receipt totals per year use sf_receipts.year_amount (the part paying that year's fees or balances carried into it), never the receipt face value; list exports pass meta.totals so export.ts appends one totals row (receipt face values, running balances and before/after values are never summed). Grade filters key on stage + grade.

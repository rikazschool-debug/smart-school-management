# support rules
- Support tickets (support_*): no direct table access; every read/write goes through support_* RPCs that derive requester/org/role from the session. Scopes: school tickets → requester, the branch principal and the org owner; platform tickets (owners/principals only) → requester and platform admins. Replies are corrected only with a kept revision, tickets are never deleted, actions are rev-checked and creates/replies/notes/info requests are idempotent by client key. Assignment grants handling of that one ticket only (support_handler); private notes stay bound to their recipient; info-request recipients read only the question via support_info_inbox; escalation copies nothing automatically. Tests: scripts/support-e2e.ts, support2-e2e.ts.
- Targets (response/resolve due) are set only by the support_sla trigger from support_settings (working hours, Asia/Riyadh); overdue is derived at read time; alerts come only from support_sla_tick, run by the existing homework tick job (no separate cron); dedupe key = exact missed target; waiting_requester pauses the resolve clock (paused_at) and resuming extends resolve_due. Reports via support_stats, scoped by support_manager. Tests: scripts/support3-e2e.ts.
- Support tables have no client grants (RPC-only). Closure tests: scripts/support4-e2e.ts (--cron for a real scheduled run), support-journey.py and support-export-journey.py on support-browser-fixture.ts.
- Org owner/principal open directed internal tickets via support_open (assignee from support_new_candidates; owner any branch, principal own branch); KPIs via support_summary; manage box includes the manager's own school tickets. Tests: scripts/support5-e2e.ts + support5-journey.py on hub4-fixture.
- Routing: tickets carry department_id (separate from category). Department/person lists come only from support_route_departments/support_route_candidates (branch members; dept = coalesce(membership, teacher) department); support_open/support_set_department re-check; routing to a department grants no access; branch transfer clears a foreign department (trigger). Create-form attachments: create_support_draft_file → files.source_type 'support_pending' → linked by support_open only when the stored object exists. Tests: scripts/support6-e2e.ts, support6-journey.py.
- Permissions: perm section "support" (view/create/assign/transfer/status/follow/followers/export/settings) through _support_ok (owner bypass, else perm_allows_user); principal defaults live in _perm_base; the UI reads support_caps only. Followers (support_followers, RPC-only) read + get alerts, never reply/attach/notes/change/export; candidates = branch staff; removal/suspension/transfer cut access. Tests: scripts/support7-e2e.ts, support7-journey.py (+ scripts/support7-prep.ts prepares its ticket).
- Assignment: default pool = active staff of the ticket branch; a person of another org branch only via _support_assign_target(cross) — owner or support.transfer on that branch — logged as cross_branch in support_events; never moves the ticket (transfer is separate). Route lists for another branch use the same check in _support_route_ok. Tests: scripts/support8-e2e.ts.
- Abandoned create-form attachments (files.support_pending) are marked cleanup_due by run_file_cleanup after 24h; younger rows (may still be uploading) and linked support files are never touched. Tests: scripts/support-cleanup-e2e.ts.
- Working hours: a ticket uses _support_hours_for (branch+department row in support_hours, else branch row, else support_settings); _support_add_work_h skips support_holidays (org-wide or the ticket's branch); both edited only via support_hours_*/support_holiday_* (settings perm). Pausing (waiting_requester) needs a reason: support_action wraps _support_action_core, stores pause_reason, cleared on resume. Tests: scripts/support9-e2e.ts, support9-journey.py (support-browser-fixture).
- Platform-run desk (Nov 8 2026, supersedes the school-manager scopes above): every ticket from any role goes to platform admins only (_support_tcan = is_platform_admin; _support_ok non-create actions platform-only); readers = requester, platform admins, assignee (replies + status via support_handler), followers. Principals/org owners keep only creating tickets. Tests: scripts/support-platform-e2e.ts.
- Maqsam calls (mq_*, src/components/support/calls.tsx): RPC-only tables; credentials are per org in mq_creds (AES-GCM via MQ_CRED_KEY, service-only _mq_creds_get/_mq_creds_put, saved only by the owner after a read-only probe passes) via src/lib/maqsam-creds.server.ts; the project MAQSAM_ACCESS_* keys are a fallback for Al-Malki only. Screens live at /app/calls (own side-menu section, tabs from calls-caps.ts); the dialer opens in one named popup window (openDialer), never an iframe. Perm section `calls` (view=branch, own=my calls, link, listen, download, export; manage = org owner); call reads via _mq_sees/_mq_can. Sync = pull of /v1/calls with a 3h overlap, upsert by (org, ext_id), throttled 1/min, triggered by opening the screens (no HTTP cron). Recordings only via mq_rec_ticket token → /api/public/maqsam/recording (re-checks the right at consume). Tickets from calls use support_create; call end never changes ticket status. Follow-up reminders: mq_followup_tick in the homework tick job, dedupe mqf:<id>. Tests: scripts/maqsam-e2e.ts (39), maqsam-journey.py on maqsam-browser-fixture.
- Internal tickets with assignment (Nov 9 2026): owners/support.create holders open branch tickets via support_open → _support_open_core; an assignee needs _support_assign_new_ok (owner or support.assign on that branch) and must be in support_new_assignees (active staff of exactly that branch); UI reads support_caps.assign_new. Live Maqsam panel (mq section "live"): dialer iframe stays mounted beside the ticket side panel; mq_live_ticket (calls.link on the chosen branch, shared service number) links the call if synced, else mq_ticket_pending («بانتظار ربط المكالمة») until mq_call_link_ticket. Tests: scripts/support-assign-e2e.ts (14).
- WhatsApp inbox (wa_*, «واتساب» tab inside «الدعم والمساعدة»): the WATI connection is bound to one org in service-only wa_connection; conversations carry org_id; every read/send/media RPC requires _wa_can = active org_owner membership of that org (no platform-admin or demo bypass); new-message alerts go to that org's owners: WATI webhook /api/public/wati/webhook stores every event in wa_webhook_events (dedupe key = hash of event type+ids+status) before _wa_process; statuses never go backwards and early ones reconcile in _wa_out_result; recovery (_wa_recover) runs on each webhook and inbox sync (no cron). Replies/files/media only via src/lib/wa-inbox.functions.ts (WATI v3 conversations/messages/text|file, messages/file/{id}); claim by client key, timeout = unknown (never retried). Tests: scripts/wa-inbox-e2e.ts.
- WhatsApp assignment (Nov 11 2026): WATI is the only assignment source — conversations/query (assignee_id, team_ids) + contacts (contact_owner, team names) pulled by waSyncAssign on tab open, every 60s while open (server throttle 30s) and right before every non-owner send (pullAssign → _wa_assign_save, changes in wa_assign_log). Owner-only links via wa_codes/wa_link_operator (WATI operator code → staff login) and wa_link_team (team code → branch), audited. Access = _wa_access: org owner (or platform admin in an org_owner session) all; perm wa_inbox.mine → chats whose assignee code is linked to me; wa_inbox.branch → chats with a team linked to a branch where I hold the grant; branch membership alone grants nothing; unlinked codes = owner only. Applied in list/messages/media/conv_ref and re-checked in waSend. No reassignment from Rikaz. Tests: scripts/wa-assign-e2e.ts (17).
- WhatsApp contact card/notes/tags/quick replies (Nov 11 2026): RPC-only tables wa_conv_tags, wa_notes, wa_quick_replies; every RPC gates through _wa_conv_ok → _wa_access (same as the chat). Card (wa_contact_card): linked students only where can_view_student, tickets only for platform admins. Notes are Rikaz-only, never sent, immutable. Tags: saved in Rikaz then pushed to WATI v3 conversations/{id}/tags (WATI accepts only predefined tags and cannot list them back; failure keeps the tag Rikaz-only, shown with a lock). Quick replies: owner edits (wa_quick_save0), inbox users read. WATI contact attributes are read-only (waContactAttrs). Voice notes: browser records audio/ogg;opus → legacy /{tenant}/api/v1/sendSessionFile?voice=true (tenant WATI_TENANT_ID, default 1056520). Tests: scripts/wa-card-e2e.ts.
- WhatsApp bot picks & live refresh (Nov 11 2026): interactive replies are read by _wa_choice (listReply/buttonReply/interactiveButtonReply) into wa_messages.body + choice_id/choice_title; webhook and WATI history share the WATI message id, so _wa_put_msg only fills missing fields, never adds a row. Bot option → branch lives in owner-only wa_bot_branches (key = WATI row id, plus a title key for history rows) via wa_bot_choices/wa_bot_link; the picked branch (wa_conversations.bot_*) is display-only and never enters _wa_access. New/changed wa_messages fire a statement trigger sending topic «wa» live_signals to _wa_live_users (owners, platform admins in that org session, wa_inbox holders); polling is only a 30s fallback. Times show via src/lib/wa-time.ts (Asia/Riyadh); _wa_ts reads millisecond epochs.

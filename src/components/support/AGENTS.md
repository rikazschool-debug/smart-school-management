# support rules
- Support tickets (support_*): no direct table access; every read/write goes through support_* RPCs that derive requester/org/role from the session. Scopes: school tickets → requester, the branch principal and the org owner; platform tickets (owners/principals only) → requester and platform admins. Replies are corrected only with a kept revision, tickets are never deleted, actions are rev-checked and creates/replies/notes/info requests are idempotent by client key. Assignment grants handling of that one ticket only (support_handler); private notes stay bound to their recipient; info-request recipients read only the question via support_info_inbox; escalation copies nothing automatically. Tests: scripts/support-e2e.ts, support2-e2e.ts.
- Targets (response/resolve due) are set only by the support_sla trigger from support_settings (working hours, Asia/Riyadh); overdue is derived at read time; alerts come only from support_sla_tick, run by the existing homework tick job (no separate cron); dedupe key = exact missed target; waiting_requester pauses the resolve clock (paused_at) and resuming extends resolve_due. Reports via support_stats, scoped by support_manager. Tests: scripts/support3-e2e.ts.
- Support tables have no client grants (RPC-only). Closure tests: scripts/support4-e2e.ts (--cron for a real scheduled run), support-journey.py and support-export-journey.py on support-browser-fixture.ts.
- Org owner/principal open directed internal tickets via support_open (assignee from support_new_candidates; owner any branch, principal own branch); KPIs via support_summary; manage box includes the manager's own school tickets. Tests: scripts/support5-e2e.ts + support5-journey.py on hub4-fixture.
- Routing: tickets carry department_id (separate from category). Department/person lists come only from support_route_departments/support_route_candidates (branch members; dept = coalesce(membership, teacher) department); support_open/support_set_department re-check; routing to a department grants no access; branch transfer clears a foreign department (trigger). Create-form attachments: create_support_draft_file → files.source_type 'support_pending' → linked by support_open only when the stored object exists. Tests: scripts/support6-e2e.ts, support6-journey.py.
- Permissions: perm section "support" (view/create/assign/transfer/status/follow/followers/export/settings) through _support_ok (owner bypass, else perm_allows_user); principal defaults live in _perm_base; the UI reads support_caps only. Followers (support_followers, RPC-only) read + get alerts, never reply/attach/notes/change/export; candidates = branch staff; removal/suspension/transfer cut access. Tests: scripts/support7-e2e.ts, support7-journey.py (+ scripts/support7-prep.ts prepares its ticket).
- Assignment: default pool = active staff of the ticket branch; a person of another org branch only via _support_assign_target(cross) — owner or support.transfer on that branch — logged as cross_branch in support_events; never moves the ticket (transfer is separate). Route lists for another branch use the same check in _support_route_ok. Tests: scripts/support8-e2e.ts.
- Abandoned create-form attachments (files.support_pending) are marked cleanup_due by run_file_cleanup after 24h; younger rows (may still be uploading) and linked support files are never touched. Tests: scripts/support-cleanup-e2e.ts.
- Working hours: a ticket uses _support_hours_for (branch+department row in support_hours, else branch row, else support_settings); _support_add_work_h skips support_holidays (org-wide or the ticket's branch); both edited only via support_hours_*/support_holiday_* (settings perm). Pausing (waiting_requester) needs a reason: support_action wraps _support_action_core, stores pause_reason, cleared on resume. Tests: scripts/support9-e2e.ts, support9-journey.py (support-browser-fixture).
- Platform-run desk (Nov 8 2026, supersedes the school-manager scopes above): every ticket from any role goes to platform admins only (_support_tcan = is_platform_admin; _support_ok non-create actions platform-only); readers = requester, platform admins, assignee (replies + status via support_handler), followers. Principals/org owners keep only creating tickets. Tests: scripts/support-platform-e2e.ts.
- Maqsam calls (mq_*, src/components/support/calls.tsx): RPC-only tables; the project Maqsam keys serve only mq_link orgs AND the MAQSAM_ORG constant in src/lib/maqsam.functions.ts (Al-Malki) — never sync/stream for another org. Perm section `calls` (view=branch, own=my calls, link, listen, download, export; manage = org owner); call reads via _mq_sees/_mq_can. Sync = pull of /v1/calls with a 3h overlap, upsert by (org, ext_id), throttled 1/min, triggered by opening the screens (no HTTP cron). Recordings only via mq_rec_ticket token → /api/public/maqsam/recording (re-checks the right at consume). Tickets from calls use support_create; call end never changes ticket status. Follow-up reminders: mq_followup_tick in the homework tick job, dedupe mqf:<id>. Tests: scripts/maqsam-e2e.ts (39), maqsam-journey.py on maqsam-browser-fixture.

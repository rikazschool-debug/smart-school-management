# Events rules (evt_*)
- RPC-only (tables have no direct read); perm sections evt_trips / evt_general / evt_courses under school_admin, checked by _evt_school_ok / _evt_ok on every call. Course delegation (evt_staff caps edit/apps/decide/attend) is granted only by school-level holders and re-read per request, so revocation is immediate.
- Course status (draft→published→completed/cancelled→archived) is separate from registration (reg_open + window) and from application status (new→review→info_needed→accepted/rejected/cancelled).
- Forms: one per course, draft + immutable published versions (evt_form_versions); _evt_check_fields/_evt_check_answers are the only validators (plain text, no markup); each application stores its form version + field snapshot.
- Public link (/join/$token, /join/track/$code) goes only through src/lib/events-public.functions.ts → service-only _evt_public_* (rate limits in evt_hits, honeypot + fill time, hashed IP). Track codes are stored as sha256 only. Applying never creates an account or student.
- Accept locks the course row then counts accepted seats (capacity exact under concurrency); client_key + partial unique indexes stop double submits/duplicates (siblings differ by name, not phone).
- Trips: guardians consent per child via evt_consent before the deadline; consents/medical data readable only with evt_trips.consents.
- Tests: scripts/evt-e2e.ts (75 checks; `--keep` writes /tmp/browser/evt/fixture.json, `teardown` removes it).
- Attachments: form field kind 'file' (accept pdf/image/doc/sheet, max_mb ≤20, max_files ≤5, always within the school file_policies). Uploads get a files row first (source evt_pending, bound to form-fill client_key or 'a:<app>' for tracking), bytes go up after (public: server-signed upload URL; signed-in: own session). The evt_app_files trigger links them on save only after checking binding + real object size; abandoned evt_pending rows are cleaned by run_file_cleanup after 24h. Event attachments are evt_item (edit cap). Read rules: _evt_item_file_ok / _evt_app_file_ok in can_read_file; public pages get 60s signed links from the server only.
- Trip consents reset (logged as consent_reset with prior answers, families notified once per rev) when location/mode/conditions/health-emergency requirements or sessions change after publishing.
- External applicant messages: evt_outbox rows (unique dedupe per app+kind+rev) drained by src/lib/evt-outbox.server.ts via WATI template WATI_EVT_TEMPLATE; without it rows wait as waiting_template and log no_template, then send once configured. Delivery callbacks: wati webhook local id evt-<id>. Template rikaz_event_update params are name,2,3,4 (verified delivery Nov 8 2026); older unsent rows for the same application are marked superseded at claim time.
- Tests: scripts/evt-closure-e2e.ts (43 checks; --keep / teardown for browser journeys).
- Section forms (evt_tpls/evt_tpl_versions/evt_tpl_log, RPC-only evt_tpl_*): four per org (trip/general/course/apply), group row (school_id null) + optional school customization (perm evt_forms.customize, active only when published and use_custom). _evt_tpl_eff picks school → group → built-in default. evt_save (wrapper over _evt_save_base) rejects a create whose tpl_version ≠ current effective (UI keeps inputs), stores extra answers + extra_fields snapshot + tpl_version; new courses copy the effective apply form into evt_forms v1 and keep it (apply_tpl_version) until evt_item_tpl_update. Core fields (_evt_core) are protected; only labels/help customizable. Tests: scripts/evt-forms-e2e.ts (38). Legacy evt-e2e/evt-closure-e2e drop the auto form to test the per-course flow.
- Calendar: the only calendar is «الفعاليات ← الملخص والتقويم» (src/components/events/calendar.tsx) = evt_calendar (_evt_ok) + adm_calendar (personal, per branch; owner loops branches) merged by mergeCalendar (dedupe kind+id+day). Staff without evt_* perms still open /app/events with the summary tab only (personal items); /app/admin/calendar redirects there. Test: src/test/unified-calendar.test.ts.

- Educational supervision (sv_*) is RPC-only (tables have RLS and no policies); identity, scope and approval rights are decided only in private._sv_* helpers. UI flags (can_work/can_approve/can_manage) are echoes of those helpers.
- Supervisor scope = a live sv_assignments row (one branch, teachers/courses/subjects, starts_at/ends_at timestamptz, Riyadh in UI) + active supervisor membership in that branch; ending it stops access at once. Ex-supervisors read old work only via an explicit owner 'read' delegation for that assignment. Teachers/principals/owners never need an assignment.
- Delegations (sv_delegations: assign/forms/approve/read) are granted only by the org owner, scoped by branch/form/record/assignment and time; never to self; an approver never approves a record they wrote or handle.
- Form definitions (sv_forms) go draft → review → published → archived; published rows are immutable (trigger); the publisher must differ from creator/last editor; principal branch customizations stay drafts until an owner/forms delegate publishes. Records keep form_id/version + form_snapshot, so later versions never change old labels.
- Records: draft may be incomplete; submit runs private._sv_missing (mirrored by missingFields in model.ts, test src/test/supervision-model.test.ts). Teacher ack/comment are separate fields and never change status. Stale rev is refused. Approve 'none' forms end at submitted.
- No scores or weights: _sv_spec_ok rejects score fields/weight keys; «لم يُلاحظ»/«لا ينطبق» exist only on indicator fields.
- Tests: scripts/supervision-e2e.ts (91 checks; --keep writes /tmp/browser/supervision/fixture.json), browser journeys scripts/supervision-journey.py and supervision-journey2.py (run supervision-journey2-prep.ts first; adoption, full record cycle, self-approval, assignment end).
- Base sv_forms rows (org_id null) are view/preview templates only; records are created only from an org-scoped published version. sv_form_adopt (owner/forms delegate) makes the fixed org copy with adopted_by/adopted_at; _sv_form_for never falls back to base.
- Plans/visits: sv3_* wrappers delegate to private implementations; sv_plan_details extends versioned sv_records, sv_scheduled_visits execution is independent from record approval. Peer participants only read the summary, own reflection and assigned actions; documentation and internal evidence remain restricted. sv3_plan snapshots allow descriptive goals without requiring arbitrary targets; old snapshots are unchanged.
- Work reports derive only from caller-scoped detail RPC snapshots in work-report.ts; list filters use filterWork over permitted rows, preventing exports from introducing broader reads or private file links.
- Approved plans remain immutable in status; sv3_plan_revision creates a separately reviewed linked record. Visit handover changes handler/scope, not original author; direct supervision storage access is denied and file delivery uses authenticated no-store server functions after RPC authorization.
- Dirty editors retain their original revision across refreshes; useUnsaved guards route and local exits without persisting private text. Plan owners come from sv3_pool; followup sessions are internal unless explicitly shared, and teacher record reads strip internal_notes/events server-side.
- Activity progress after plan approval lives only in sv_plan_progress (append-only, sv3_plan_progress_save/list, sv3_my_actions); the approved plan record never changes and the action owner never verifies their own activity.
- Handed-over visits: the current handler reads the linked record (private._sv3_record_read) so reports load; writing still follows record rules. Visit editors pin the opening rev so background refreshes never overwrite silently.
- Stage 4 (sv4_*): RPC-only tables; scope = private._sv4_work (owner/principal/live covering assignment) and _sv4_lead for approvals. Needs are reviewed by someone other than creator/teacher; dev plans are versioned (version_of, one open revision, old version → superseded) and approval/execution (sv4_activity_log, append-only; owner of an activity never verifies it)/impact (evidence required) stay separate. planMissing in pd-model.ts mirrors _sv4_plan_missing (test src/test/supervision-pd.test.ts).
- Programs: hours only from present attendance on non-cancelled sessions (unique per session/user); registration ≠ attendance; meeting links https only; meetings/minutes/tasks reuse adm_* and are only linked via sv4_meeting_links. Evaluations work only with an org-adopted sv_forms copy (_sv_form_for), store snapshots, show counts only and hide breakdowns under 3 responses. HR reads verified hours via sv4_hr_hours (_hr_school_ok view) without notes. Evidence and remaining items: docs/supervision-stage4-report.md.

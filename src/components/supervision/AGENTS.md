- Educational supervision (sv_*) is RPC-only (tables have RLS and no policies); identity, scope and approval rights are decided only in private._sv_* helpers. UI flags (can_work/can_approve/can_manage) are echoes of those helpers.
- Supervisor scope = a live sv_assignments row (one branch, teachers/courses/subjects, starts_at/ends_at timestamptz, Riyadh in UI) + active supervisor membership in that branch; ending it stops access at once. Ex-supervisors read old work only via an explicit owner 'read' delegation for that assignment. Teachers/principals/owners never need an assignment.
- Delegations (sv_delegations: assign/forms/approve/read) are granted only by the org owner, scoped by branch/form/record/assignment and time; never to self; an approver never approves a record they wrote or handle.
- Form definitions (sv_forms) go draft → review → published → archived; published rows are immutable (trigger); the publisher must differ from creator/last editor; principal branch customizations stay drafts until an owner/forms delegate publishes. Records keep form_id/version + form_snapshot, so later versions never change old labels.
- Records: draft may be incomplete; submit runs private._sv_missing (mirrored by missingFields in model.ts, test src/test/supervision-model.test.ts). Teacher ack/comment are separate fields and never change status. Stale rev is refused. Approve 'none' forms end at submitted.
- No scores or weights: _sv_spec_ok rejects score fields/weight keys; «لم يُلاحظ»/«لا ينطبق» exist only on indicator fields.
- Tests: scripts/supervision-e2e.ts (91 checks; --keep writes /tmp/browser/supervision/fixture.json), browser journeys scripts/supervision-journey.py and supervision-journey2.py (run supervision-journey2-prep.ts first; adoption, full record cycle, self-approval, assignment end).
- Base sv_forms rows (org_id null) are view/preview templates only; records are created only from an org-scoped published version. sv_form_adopt (owner/forms delegate) makes the fixed org copy with adopted_by/adopted_at; _sv_form_for never falls back to base.
- Plans/visits: sv3_* wrappers delegate to private implementations; sv_plan_details extends versioned sv_records, sv_scheduled_visits execution is independent from record approval. Peer participants only read the summary, own reflection and assigned actions; documentation and internal evidence remain restricted. sv3_plan snapshots allow descriptive goals without requiring arbitrary targets; old snapshots are unchanged.
- Work reports derive only from caller-scoped detail RPC snapshots in work-report.ts; list filters use filterWork over permitted rows, preventing exports from introducing broader reads or private file links.
- Approved plans remain immutable in status; sv3_plan_revision creates a separately reviewed linked record. Visit handover changes handler/scope, not original author; direct supervision storage access is denied and file delivery uses authenticated no-store server functions after RPC authorization.
- Dirty editors retain their original revision across refreshes; useUnsaved guards route and local exits without persisting private text. Plan owners come from sv3_pool; followup sessions are internal unless explicitly shared, and teacher record reads strip internal_notes/events server-side.
- Activity progress after plan approval lives only in sv_plan_progress (append-only, sv3_plan_progress_save/list, sv3_my_actions); the approved plan record never changes and the action owner never verifies their own activity.
- Handed-over visits: the current handler reads the linked record (private._sv3_record_read) so reports load; writing still follows record rules. Visit editors pin the opening rev so background refreshes never overwrite silently.
- Stage 4 (sv4_*): RPC-only tables; scope = private._sv4_work (owner/principal/live covering assignment) and _sv4_lead for approvals. Needs are reviewed by someone other than creator/teacher; dev plans are versioned (version_of, one open revision, old version → superseded) and approval/execution (sv4_activity_log, append-only; owner of an activity never verifies it)/impact (evidence required) stay separate. planMissing in pd-model.ts mirrors _sv4_plan_missing (test src/test/supervision-pd.test.ts).
- Programs: hours only from present attendance on non-cancelled sessions (unique per session/user); registration ≠ attendance; meeting links https only; meetings/minutes/tasks reuse adm_* and are only linked via sv4_meeting_links. Evaluations work only with an org-adopted sv_forms copy (_sv_form_for), store snapshots, are accepted only while the program is open, and show counts only after closing with ≥3 responses (no free text, named list alphabetical) so successive summaries cannot be differenced. HR reads verified hours via sv4_hr_hours (_hr_school_ok view) without notes. Evidence and remaining items: docs/supervision-stage4-report.md.
- HR PD hours screen (src/components/hr/pd-hours.tsx on /app/hr/training) reads only sv4_hr_hours_org (branches where _hr_school_ok view; present attendance on scheduled sessions; ≤1 year; no notes); totals dedupe per session+user. It sits beside HR training and never replaces it.
- Stage 5 learning outcomes (sv5_*): RPC-only. Measures are either a published Rikaz test read live from homework_grades (no copy, no parallel gradebook) or documented external results in sv5_results; missing = no row (never zero), absent/exempt are statuses. Scope = _sv5_scope (owner/principal or live assignment covering subject/course/teacher) for writes; course teacher reads own. Import: sv5_import_preview never writes; sv5_import_confirm re-checks the same rows (fingerprint) and writes valid rows only in one transaction; identity by national ID/C-Smart only. Mastery sets are owner-published by someone other than the editor and frozen; skills/items only with a documented mapping; sv5_compare refuses different subject/scale/standardized kind and keeps point difference and percent change separate. Client model lo-model.ts (test src/test/supervision-lo.test.ts); RPC journey /tmp/browser/sv449/lo.py.
- Stage 5 improvement actions (sv5_act_*): RPC-only; created only from a measure in write scope with a frozen analysis snapshot; students only from that measure's targets; approval by _sv4_lead never by creator/responsible; execution (start/followup/done/cancel) never sets impact; impact needs a later same-subject measure, by someone in scope other than the responsible, and incomparable = not_comparable only. Links store references; titles only via the item's own read rule. actMissing (act-model.ts) mirrors _sv5_act_missing (test src/test/supervision-act.test.ts); journey /tmp/browser/sv449/act.py.
- Stage 5 resources (sv5_res_*): RPC-only, versioned per series (published immutable by trigger, one open draft, new version reuses sv5_resource_files references); writers via _sv5_res_writer, publisher _sv5_res_lead and never writer/last editor; readers _sv5_res_read (published = group/branch staff, drafts = writer + publishers); files only text/PDF/PNG/JPEG/WebP through can_read_file. Library shows them read-only via SupervisionShelf. resMissing/OFFICIAL_CLAIM in res-model.ts mirror the server (test src/test/supervision-res.test.ts).
- Wrapping public.can_read_file by rename must be followed by recreating policies "files read", "rikaz files read" and "rikaz files upload" in the same migration: policies bind the function by OID and would keep calling the renamed one.
- Stage 5 portfolio (sv5_pf_*): RPC-only; items reference a final source of the teacher (approved record, present PD attendance, approved dev plan, done action they own) with a title/date/description snapshot only — never files or notes. Only the teacher proposes/edits/withdraws; verify/return via _sv5_pf_reviewer (_sv4_work, never the teacher); verified rows immutable by trigger; source links only when the source's own read rule passes. groupPf/pfRows in pf-model.ts (test src/test/supervision-pf.test.ts).
- Stage 5 dashboard (sv5_dash): read-only; every indicator is built from rows filtered by that source's own read helper, so the dashboard can never show more than the source screens; rows (≤300) and totals come from the same query. Never read edu_* (guidance cases) here. indValue/summaryRows in dash-model.ts (test src/test/supervision-dash.test.ts).
- Forms library: field metadata (example, look_for, level_desc, evidence on indicators, private) and spec steps/print are validated only by private._sv_spec_ok; the indicator evidence rule lives in private._sv_missing and is mirrored by missingFields. Private fields are stripped server-side in sv_rec_get for the record's teacher (private_hidden), never only in UI. Library/compare/progress helpers live in forms-model.ts (test src/test/supervision-forms.test.ts); print HTML (form-print.ts) feeds both the preview iframe and printing so they cannot diverge. New template versions are base rows; org copies move only via sv_form_draft from the template + publish by someone else. Journeys: /tmp/browser/sv460/forms.py, priv.py, pilots.py, formsui.py.

- Educational supervision (sv_*) is RPC-only (tables have RLS and no policies); identity, scope and approval rights are decided only in private._sv_* helpers. UI flags (can_work/can_approve/can_manage) are echoes of those helpers.
- Supervisor scope = a live sv_assignments row (one branch, teachers/courses/subjects, starts_at/ends_at timestamptz, Riyadh in UI) + active supervisor membership in that branch; ending it stops access at once. Ex-supervisors read old work only via an explicit owner 'read' delegation for that assignment. Teachers/principals/owners never need an assignment.
- Delegations (sv_delegations: assign/forms/approve/read) are granted only by the org owner, scoped by branch/form/record/assignment and time; never to self; an approver never approves a record they wrote or handle.
- Form definitions (sv_forms) go draft → review → published → archived; published rows are immutable (trigger); the publisher must differ from creator/last editor; principal branch customizations stay drafts until an owner/forms delegate publishes. Records keep form_id/version + form_snapshot, so later versions never change old labels.
- Records: draft may be incomplete; submit runs private._sv_missing (mirrored by missingFields in model.ts, test src/test/supervision-model.test.ts). Teacher ack/comment are separate fields and never change status. Stale rev is refused. Approve 'none' forms end at submitted.
- No scores or weights: _sv_spec_ok rejects score fields/weight keys; «لم يُلاحظ»/«لا ينطبق» exist only on indicator fields.
- Tests: scripts/supervision-e2e.ts (91 checks; --keep writes /tmp/browser/supervision/fixture.json), browser journeys scripts/supervision-journey.py and supervision-journey2.py (run supervision-journey2-prep.ts first; adoption, full record cycle, self-approval, assignment end).
- Base sv_forms rows (org_id null) are view/preview templates only; records are created only from an org-scoped published version. sv_form_adopt (owner/forms delegate) makes the fixed org copy with adopted_by/adopted_at; _sv_form_for never falls back to base.

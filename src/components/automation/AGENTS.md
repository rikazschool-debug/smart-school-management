# automation rules
- Phase E: notify/reminder channels use au_channels and the approved au_wa_templates mirror; WhatsApp stays simulated until both explicit live gates allow it, and _au_msg_guard rechecks authority, source, recipient, consent and frozen template values before claiming. Unknown results never retry automatically. PDF/XLSX rendering uses au_files plus the server worker; scheduling that worker is separate from the unchanged database jobs. Tests: automation-platform-e-e2e, au-e-journey.py.
- Automation center (au_*): Postgres engine only — registries (au_sections from perm_catalog, au_events/variables/operators/actions/recipients/trigger_types) are the single source; each wired event has one closed adapter in _au_src (scan, simulation and execution-time recheck) and instant events enqueue via the _au_trg after-insert trigger in the same transaction (never failing the user write); rules = {schedule, when, steps} with per-rule next_run_at (no cron per rule), worked by the central rikaz-automation job plus rikaz-homework-tick; recipients resolve from memberships/_perm_allows_user at execution; events covered by existing jobs stay blocked; owner-only RPCs; rules start inactive; au_registry_gaps must stay empty; every undelivered recipient is logged in au_skips (no silent drops), cross-rule conflicts resolve by priority, over-cap items defer then cancel with a reason; guardian recipients are in-app only, never on restricted or already-family-notified events. Tests: automation-phase4b-e2e. Tests: automation-e2e, automation-registry-e2e, automation-phase4-e2e. Designer (src/components/automation/designer/flow.ts) only converts graph↔engine definition; the server (au_validate/au_rule_save_full) stays the single validator, layout is stored beside the draft, approve≠activate. Automation e2e suites take turns via scripts/lib/au-suite-lock.ts and tick via auTick (global worker). Tests: automation-phase5-e2e. Access: owner, or perm-tree grant (au_view/au_manage/au_control, never automatic) + live owner-made au_delegations scope checked by _au_need*/_au_vis in every au_* RPC; lifecycle validate→simulate→submit→review(risk>low)→approve→activate, no self-approval, approve/activate senior roles only, high risk owner only; _au_exec rechecks approver/activator authority. Tests: automation-phase6-e2e (suites approve via scripts/lib/au-approve.ts).
- Automation data sources (ds.*): au_sources is the registry (every API catalogue resource has exactly one status; covered rows name covered_by); internal sources are closed readers in _au_ds, catalogue sources (ds.api.*) go through the one generic reader _au_ds_api over _api_rows_all, all behind _au_srcp (fields = registered au_variables only, sensitive/free-text catalogue fields never registered, org/school limits and section_enabled always applied); perm_sections entries are `section[:action]` checked by _au_ps_ok inside _au_ds_ok (used by _au_can_on, au_registry, au_lookup); au_lookup rejects foreign schools and pages; scans advance au_rules.scan_cursor in batches and a failing scan is logged (scan_error/fin_mismatch) without stopping other rules; bulk balances use _sf_balances, which must stay identical to _sf_balance (never edit _sf_balance for automation) and _au_fin_guard blocks results on mismatch. catalogue reads are true windows: _au_ds_api sets au.win_* GUCs read by _au_lo/_au_hi/_au_ex/_au_lim inside _api_rows..v4 (plpgsql, force_custom_plan) — keep any new _api_rows branch windowed; full finance parity is _au_fin_parity (service-only, batched, no sampling); au_data grants read-only automation access to meetings/circulars/gate and never the operational action. Tests: automation-platform-b-e2e, automation-platform-b2-e2e, automation-platform-b3-e2e, automation-fin-parity-e2e, automation-platform-b-perf, automation-platform-b2-perf (50000).
- Recipients (phase C): a step may carry `groups` (1–5; by person/role[all|specific|linked]/title/category/dept/manager 1–3/record/step, optional schools|central and one fallback); _au_check_groups validates, _au_groups resolves+dedupes and rechecks via _au_rcpt_allowed (g:staff), empty groups log no_recipient:groupN (never a random pick); per-step recipients persist in au_step_people; permanent school responsibilities live in school_responsibilities (+ org_docs/mt_buses.responsible_user) set only by owner RPCs. UI: designer/groups.tsx over au_rcpt_options + people_pick purpose automation. Tests: automation-platform-c-e2e.
- Operational actions (phase D): mt_request/hr_letter/report/set run only through closed internal helpers (_au_act_*) that reuse the section's own path (mt numbering+mt_events via _au_mt_ev, hr_letters requested→human review, au_update_fields whitelist) under the approver's authority rechecked at execution; outputs live in au_step_out and are re-read live (out_<key>_*); grouped mode (mode=batch, ds.* only) recounts via _au_batch_ctx before every step; wait_until reschedules on the same path; business failures log au_skips and run on_fail; reports are server snapshots in au_reports read only via RLS (shared + active, or owner) and rendered with src/lib/export.ts; HR letters are never issued automatically. Tests: automation-platform-d-e2e, au-d-journey.py.
- Automatic report files: automation_tick → _au_worker_kick (pg_net, only when au_files pending) → /api/internal/automation/worker, whose bearer is checked by service-only _au_worker_check against Vault; no extra cron, no app secret.
- Templates (phase 7): au_templates (org_id null = platform library, else group) + immutable au_template_versions, RPC-only (au_tpl_list/use/save/set_status); a template is a definition with `$p:key`/`$m:key` placeholders filled by _au_tpl_fill within declared min/max, validated by the engine (_au_check_def) and saved through au_rule_save_full as an inactive draft — never a parallel engine; listed risk comes from _au_risk; group templates are owner-only and versioned; no fixed schools/staff/amounts in public templates. Tests: automation-templates-e2e.
- Sanad drafts (phase 8): sanadAutomationDraft runs as the caller (RLS client), sends only registry metadata + the user's text to the existing Gemini key, validates with au_validate, and never saves/approves/activates — saving is a user click through au_rule_save_full. Tests: automation-sanad-e2e.
- Registry tables read directly by the UI (au_channels, au_source_tables) are readable only via _au_reader() (owner, live delegation or platform admin), never plain membership.
- Sanad rule inspection consumes only caller-authorized au_rule_get/au_simulate_def/au_jobs_list results; deterministic summaries never write or call a model, and sampled simulation/run results remain explicitly partial.

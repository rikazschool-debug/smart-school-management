# Timetable rules (enforced in SQL; this UI mirrors them)
- Timetables: one source (timetables + timetable_slots); slots are editable only while the timetable is a draft and every insert/update is re-checked by check_slot (real clock overlap, assignment, availability, loads, special rooms); publishing goes only through publish_timetable (tt_validate: full weekly counts, doubles, stale base) and revisions through start_timetable_revision (copies pins); current_timetable() picks the version for a date. Auto-generation is a deterministic constraint solver (src/lib/timetable-solver.ts, no AI) run in a Web Worker; the server owns input snapshots and application (tt_gen_start/finish/apply/ignore, input-hash freshness). Role views filter the same data — never copy it per role. Brief: docs/timetable-package-brief.md.

# School administration rules (enforced in SQL; this UI mirrors them)
- Virtual meetings: adm_meetings.mode='virtual' rooms use Agora for media only; tokens come from src/lib/meeting-live.functions.ts after adm_live_join (re-checked on every renewal); moderation/state live in adm_live_* RPCs and provider enforcement runs only through the service-role queue adm_meeting_revocations (Agora kicking-rule REST). Owners may organize org-scope meetings; invitees resolve via _adm_invitee_school. Tests: scripts/meetings-live-e2e.ts.
- School administration (adm_*): forms (versioned, principal-only setup, one handler) → requests (snapshot of fields, rev-checked) and tasks (one assignee, optional confirmation) are written only via adm_* RPCs; adm_events is the shared activity log; files use source_type='admin' + category; owners get counts only (adm_org_summary). Duties: duty_setup (default principal) sets posts/policy/exemptions, duty_rosters (default principal+vice; owner-delegable, deny wins, via _adm_duty_view/_manage/_setup) drafts→suggest (_duty_busy: classes, substitutes, absence, unavailability, overlap, cap)→publish (snapshot per version); edits after publish are explicit (cancel with reason, one-day substitute row) and timetable/substitution/absence changes only alert via _duty_check_conflicts — never silent redistribution. Meetings: organizer-only edits/send/cancel/confirm minutes (versioned; post-confirm edits = new version with reason); restricted meetings readable only by organizer/writer/invitees (adm_can_read_meeting); each decision creates exactly one adm_tasks row (decision_id) and its status is the task status. adm_calendar is personal only. Tests: scripts/admin-e2e.ts, scripts/admin2-e2e.ts.
- Tasks are created/reassigned only inside the creator scope (_task_target_ok: principal any staff, vice scope teachers, supervisor assigned teachers); meetings are organized by principal (own school), org owner, or a person the owner granted meetings.organize or hub_meetings.create (_adm_can_organize). Hub meetings perms are checked live on the server via _adm_hub: start → host role in _adm_live_role (re-checked on every token renewal/host action), attend → adm_meeting_attendance. Tests: scripts/hub-meet-e2e.ts.
- Class virtual sessions are adm_meetings rows with course_id (scheduled independently of the timetable via vc_* RPCs); _adm_live_role gives host to the assigned course teacher and member to currently enrolled students, and admin meeting lists exclude course_id rows. Tests: scripts/vc-e2e.ts.
- Category meeting invites: adm_meetings.audience (validated by _adm_meet_target, resolved via _bc_pool; students excluded) is stored only on drafts via adm_meeting_set_audience with a fingerprint; adm_meeting_send refuses if the re-resolved list differs. Audience rows are adm_meeting_members.via=audience; guardians stay valid through _adm_member_ok. Suspending comm_hub (platform_set_section) blocks notices, org-scope meetings/live roles and wider-than-school circulars; records are kept. Tests: scripts/hub-aud-e2e.ts.

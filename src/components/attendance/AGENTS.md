# attendance UI rules
- Student cards are auto-issued by DB triggers on student insert/activation and enrollment (_auto_card); tokens are 10 random digits (_new_card_code) so the CODE128 barcode stays short and scannable. issue_student_card without a reason returns the existing card; a replacement needs a reason.
- scanner.tsx: BarcodeDetector (code_128/qr/code_39/ean_13) with ZXing fallback; scans are queued, never dropped; the same code is ignored for 2s; nothing is recorded until server_now is verified.

- Attendance: attendance_days (one row per student/day) is separate from gate_movements (in/out/return), pickup_requests (quick|permission lifecycle) and call_queue; all writes via RPCs (scan_attendance, manual_attendance, build_absence_review, resolve_absence, *_attendance_correction, create/decide/cancel_pickup, pickup_arrived/progress, handover_pickup, record_return, call_next/result). Time is always the server clock (Asia/Riyadh); classification is att_classify on the versioned policy from attendance_policy(school,date) — policies are never backdated. Exit is recorded only by handover_pickup; the barcode is never an exit pass. Security/teachers read requests only through pickup_queue (no reason). One-time pickup delegates live on the pickup_request (single use, same day, separate approval via decide_delegate, ID-last-4 match plus explicit staff confirmation at pickup_arrived(_id,_id_last4,_confirmed), locked after 3 mismatches); delegate phone/ID columns are not column-granted — read only via pickup_delegate_detail/delegate_reviews. Absence review is built server-side by att_tick (cron every 10 min all day; only due schools without an ok run today, retry up to 12 attempts with approver alert, logged in attendance_tick_runs, status via att_tick_status; _now/_only args are for service-role tests only) from enrollments valid on the date (_att_expected). Scan, gate and call queue live together in /app/attendance-station; name/code check-in uses att_search_students + checkin_student (same rules as a card scan). Staff day lists use att_day_rows (names without student-record access). Scanning is blocked until server_now is verified. Tests: scripts/attendance-e2e.ts, scripts/att-browser-fixture.ts.
- Card/camera/name check-in (scan_attendance, checkin_student, att_search_students) needs att_scanner (security role, or an owner grant gate.scan; deny wins); other roles keep manual entry, returns and records. UI mirrors grants via useSchoolPerms.
- Gate «نداء» button (pickup list): src/lib/announcer.ts — one in-browser queue per device, each call is one natural Arabic clip from speakArabic (src/lib/announce.functions.ts, AI Gateway TTS, cached per text) played 3 times, browser Arabic voice only as fallback, never overlapping; the server call_queue/speaker screen is unchanged.

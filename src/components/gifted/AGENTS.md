- Gifted care hub (gifted/hub.tsx) tabs come from gt_me; coordinator = private._gt_coord (owner, counselor, or gifted_care manage grant); principal/vice read only with gifted_care view grant (no indicator texts).
- Nominations (gt_nominations) are written only via gt_nom_save (teacher of the student or coordinator; draft/sent), gt_nom_evidence (append) and gt_nom_act (coordinator: review/needs_info/approve/reject, reason required, nominator never decides own). One domain per student per academic year; rev guards stale edits; every change goes to gt_events. nomIssues/nomActions in model.ts mirror the server.
- An approved nomination means school care only — never official qualification or an external measure result. Old edu_records kind talent stay readable under «سجل الطلبة». Tests: scripts/gifted-e2e.ts, src/test/gifted-model.test.ts.
- Care plans (gt_plans + gt_plan_students per-student goal_status/acts_done) are written only by the coordinator via gt_plan_save/act/copy; statuses draft/ready/running/review/closed, readiness in private._gt_plan_check (mirrored by planIssues), close needs a result; after start goals/activities/students can only grow. Follow-ups (gt_followups) only via gt_plan_follow on running/review plans, immutable; a goal becomes achieved only with written evidence — activities done never count as goals. Copy carries no students, follow-ups or evidence.
- External measures (gt_measures) are coordinator-only (write and read); gt_student_file returns measures=null to others. No result ≠ not gifted.
- Programs (gt_programs: school or external) and participants (gt_participants) are coordinator-written via gt_prog_save/act/target and gt_part_act; nomination, registration, attendance, completion and consent are separate fields. Register needs approved + consent granted/not_needed + free seat; attendance needs registration; completion needs attendance. External opportunities need organizer, source URL and manual verified_on; the platform never registers, pays or sends data to outside bodies. canRegister in model.ts mirrors the server.
- Guardian consent only via gt_consent by a verified guardian of that student (private._gt_guardian_of); 'ack' records acknowledgement and never changes consent. Consent requests are in-app notifications only. Calendar is derived client-side (calendarItems) from programs and plans.
- Works (gt_works + gt_work_members): kinds project/participation/achievement written only by the coordinator via gt_work_save; kind never changes, so participation stays separate from winning; editing a verified record returns it to pending. gt_work_verify needs an attached file or link, a reason when rejected, and another coordinator when one exists. Group achievements count once (workStats).
- Evidence files: gt_work_attach creates files rows (source_type gt_evidence, path <school>/gt/<id>) before upload to private rikaz-files; can_read_file opens them only for _gt_viewer of the work's school via short-lived signed URLs. No shared gallery exists; publishing student work would need a separate explicit permission + consent.

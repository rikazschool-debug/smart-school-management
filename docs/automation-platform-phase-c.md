الحالة: **منفّذ ومختَبَر على قاعدة الاختبار** — لم يُفعَّل أي قاعدة، ولم يُرسل أي شيء خارج المنصة، ولم تتغير المهام المجدولة الـ13 ولا `_sf_balance` ولا إعدادات WATI ولا الإنتاج.

## 1. ما بُني

### طرق اختيار المستلمين (مجموعات داخل الخطوة)
كل خطوة إشعار/تذكير/تصعيد/مهمة/طلب مراجعة تقبل `groups` (1–5 مجموعات)، ولكل مجموعة طريقة واحدة:

| الطريقة | المصدر الفعلي في النظام |
|---|---|
| موظف بالاسم (`person`) | قائمة الأشخاص المعتمدة `people_pick` بغرض `automation` (أسماء فقط) |
| الدور (`role`) — الجميع / أشخاص محددون / المرتبط بالسجل | العضويات الحالية + القواعد القائمة `_au_rcpt` |
| المسمى الوظيفي (`title`) | `hr_assignments.job_title` السارية |
| التصنيف الوظيفي (`category`) | `hr_assignments.category_id` ← `hr_job_categories` |
| القسم (`dept`) رئيسي أو أكاديمي | `hr_assignments.department` / `memberships.department_id` |
| المدير المباشر وما فوقه 1–3 (`manager`) | سلسلة `hr_assignments.manager_id` |
| المسؤول المرتبط بالسجل (`record`) | المسؤوليات الدائمة للمدرسة، مسؤول الوثيقة، مسؤول المركبة، رئيس القسم، والعلاقات الموجودة (المكلَّف، المعلم، ولي الأمر…) |
| مستلمو خطوة سابقة (`step`) | جدول `au_step_people` لكل تنفيذ |

قيود اختيارية لكل مجموعة: مدارس محددة، أو الإدارة المركزية (للأشخاص/الأدوار)، وبديل واحد (fallback) إن لم يوجد أحد مؤهل.

### المسؤوليات الدائمة
- `school_responsibilities`: محاسب، صيانة، نقل، موارد بشرية، وثائق — لكل مدرسة شخص واحد.
- `org_docs.responsible_user` و`mt_buses.responsible_user` لمسؤول الوثيقة والمركبة.
- التحديد عبر دوال لمدير النظام فقط (`school_resp_set`, `org_doc_set_responsible`, `mt_bus_set_responsible`) ويجب أن يكون الموظف نشطًا في المدرسة نفسها؛ كل تغيير يُسجّل.
- الواجهة: زر «المسؤوليات» في بطاقة كل مدرسة (صفحة المدارس والفروع) لمدير النظام.

### سلوك التنفيذ
- حذف التكرار بين المجموعات: كل شخص يصله الإشعار أو المهمة مرة واحدة.
- إعادة التحقق من كل شخص عند الحفظ والمحاكاة والتنفيذ وإعادة المحاولة (`_au_rcpt_allowed` + `_au_deliver`).
- لا اختيار عشوائي: مجموعة بلا أحد وبلا بديل تُسجَّل `no_recipient:groupN` في `au_skips`؛ والشخص غير المؤهل يُسجَّل `not_allowed:…`.
- المهام: مهمة لكل شخص مؤهل (حتى 10) عبر مسار التكليفات القائم، دون تكرار عند إعادة التشغيل؛ ولي الأمر لا يُكلَّف.
- المحاكاة تعرض لكل مجموعة: الطريقة، عدد المؤهلين والمستبعدين، أول 10 أسماء، و«لا يوجد مستلم» إن وُجد.

### المصمم
لم يُعَد بناء المصمم: أضيف خيار «اختيار متقدم للمستلمين» داخل خصائص الخطوة نفسها، وحقل «اسم الخطوة» لاستخدام مستلميها لاحقًا، وعرض المجموعات في نتيجة المحاكاة. الاختيار القديم بالفئات بقي كما هو.

## 3. ملاحظات أمنية
- الدوال الداخلية (`_au_people`, `_au_groups`, …) غير متاحة للمستخدمين.
- الدوال المتاحة للمستخدم المسجّل (`au_rcpt_options`, `school_resp_*`, `org_doc_set_responsible`, `mt_bus_set_responsible`, `au_people_titles`) تتحقق داخليًا من مدير النظام أو التفويض الحي؛ تنبيه الفاحص عنها متوقع وفق نمط المشروع (الوصول عبر RPC فقط).
- `school_responsibilities` و`au_step_people` بلا سياسات عمدًا: لا قراءة مباشرة إلا عبر الدوال.

## 4. إغلاق نواقص C (26 نوفمبر)
- مسؤول الوثيقة داخل نموذج تعديل الوثيقة، ومسؤول المركبة داخل نموذج تعديل الباص (مدير النظام فقط)، مع عمود «المسؤول» في قائمة الوثائق وتسجيل كل تغيير (`access_audit` للوثائق، `mt_bus_events` للباصات).
- مراجعة أمنية للأدوات الست (`automation-platform-c2-e2e` 45/45): رفض الاستدعاء المجهول، رفض غير المالك، عزل المنظمات، المنحة دون تفويض لا تكفي، التفويض لا يتجاوز مدارسه، التفويض المنتهي يُغلق الوصول.
- ثغرتان وُجدتا وأُغلقتا: (1) `au_people_titles` كانت تعرض مسميات موظفين خارج مدارس التفويض؛ (2) كان يمكن للمفوَّض حفظ قاعدة تسمّي أشخاصًا خارج مدارسه — صار الحفظ والمحاكاة يرفضان ذلك (`_au_pick_ok`)، بينما تبقى حالة النشاط تُفحص وتُسجَّل وقت المحاكاة والتنفيذ.
- محاكاة القاعدة المحفوظة (`au_simulate`) صارت تحلّ المجموعات أيضًا (كانت تعرضها في المصمم فقط).
- تغيير المسؤول بين الاعتماد والتنفيذ: التنفيذ يصل للمسؤول الجديد فقط (مختبر).
- مراجعة بصرية بحساب مدير نظام اصطناعي (`au-c-journey.py` 6/6): نموذج الوثيقة، نموذج الباص، نافذة المسؤوليات، محرر المجموعات في المصمم؛ بلا أخطاء صفحة.

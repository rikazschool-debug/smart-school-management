## ترتيب النشر والرجوع

1. فحص PR كامل ثم دمج عادي يحفظ التاريخ، ثم فحص main للإصدار الثابت. لا تغيير للسحابة أو أسرارها؛ فحص انحرافها الحالي للقراءة فقط عبر الآلية القائمة.
2. اعتماد manifest نفسه بعد مطابقة الترحيلات الست الجديدة فعليًا؛ مراجعة المصنفات العامة للدوال/المنح لا تعني السماح بأي DDL آخر. استخدام بوابة GitHub وproduction-vps والمشغّل المحمي الحالي، دون مسار نشر موازٍ.
3. المشغّل يعيد فحص الهوية والتوافق والبناء المعزول، ويأخذ نسخة أخرى فورية قبل التطبيق ويختبر استعادتها. يطبق المعلّق فقط، كل ملف وسجله بمعاملة واحدة، ثم يبدّل صورة التطبيق وحدها. يحفظ حدود التسليم والأسرار وNginx ويعيد مشغّل الرسائل لحالته السابقة دون تفريغ الطوابير.
4. فحص الصفحات والخدمات والترويسات والصورة والسجل وعدادات البيانات. فحص OPTIONS الصحيح/المرفوض وPOST ناقص من أصل Replit، دون هوية أو OTP. انتظار 3.2 ثانية بين طلبات المسارات المحدودة للمحافظة على حد Nginx القائم.
5. صورة التطبيق السابقة محفوظة. عند فشل التطبيق، تتوقف العملية وتُراجع مرحلة الفشل؛ يمكن إعادة الصورة السابقة مع إبقاء الأعمدة الاختيارية والسجل الجديد، بعد التحقق من التوافق. تعريفات الدوال السابقة محفوظة لإصلاح أمامي محدود عند الحاجة، وليست تعليمات لعكس الترحيلات تلقائيًا.
6. لا reset ولا restore فوق بيانات أحدث ولا حذف للأعمدة الجديدة أو صفوف سجل الترحيلات. نسخة القاعدة وسيلة تعافٍ طارئ مدروس فقط؛ لا تُستخدم لطمس العمليات التي حدثت بعد النسخ. مفاتيح وأسرار وقيود MCP والخدمات الحالية لا تتغير.

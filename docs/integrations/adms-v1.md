### السلوك
- **المصادقة:** HMAC-SHA256 على `METHOD\nPATH?QUERY\nKEY_ID\nTIMESTAMP\nNONCE\nsha256(raw body)`، نافذة ±300 ث، مقارنة ثابتة الوقت، مفاتيح مستقلة لكل مؤسسة واتجاه. مفتاح الاستقبال مربوط بالزوج (bridge org, Rikaz org) ونطاق `events:ingest`؛ أي اختلاف 403.
- **منع replay:** `(key_id, nonce)` بقيد فريد 10 دقائق في `adms_nonces` داخل معاملة الحفظ نفسها؛ المكرر 409 `request_replayed`.
- **الحفظ قبل الإقرار:** `_adms_ingest` (خدمي فقط) يحفظ nonce وكل حركة في معاملة واحدة؛ الرد 200 يُبنى من النتيجة بعد COMMIT. تفرّد `(bridge_org_id, event_id)` مع بصمة الحمولة: مطابق ← `duplicate` بالإيصال نفسه؛ مختلف ← `rejected/event_id_payload_conflict` ويُحفظ في `adms_conflicts` دون overwrite. الخام append-only بمشغّل يمنع التعديل والحذف.
- **نتيجة لكل حركة:** accepted/duplicate (durable + receipt_id) أو rejected برمز: `invalid_event`، `time_inconsistent` (الوقت الخام − 03:00 ≠ UTC)، `scope_or_mapping_requires_review`. فشل الحفظ ← 503 دون أي إقرار.
- **المزامنة:** health يجب أن يعيد org_id المربوط؛ كل صفحة تُطبّق مع مؤشرها في معاملة (`_adms_apply_page`) وبفحص أن المؤشر لم يتغير؛ upsert بمعرف الجسر، remove = تعطيل وسحب مع حفظ الربط والتاريخ؛ تعارض الملكية يوقف التطبيق. ربط مؤسسة الجسر بمؤسسة ركاز يتم عند أول تطبيق ناجح من زوج المفتاح الخادمي، ولا يتبدل بعد ذلك (مشغّل).
- **الربط:** موقع الجسر ← فرع أو موقع إداري (`adms_admin_sites`، بلا مدرسة)، واحد فقط. الجهاز القديم في ركاز يُربط بجهاز الجسر صراحة فقط؛ لا دمج بالاسم أو SN.
- **مطابقة PIN:** صريحة فقط على `(org, bridge_device_id, pin)`؛ رقم الموظف يظهر «اقتراحًا» يحتاج نقرة. غير المطابق يبقى `unmatched` بلا موظف.
- **المعالجة منفصلة:** `_adms_process` يكتب بصمة `hr_att_punches` (source=device، key=`adms:<org>:<event>`) ثم حساب اليوم، فقط إذا `processing_enabled` (افتراضيًا false، يغيّره المالك فقط عبر `adms_processing_set`، بلا زر في الواجهة). لا إشعارات، ولا أثر رواتب إلا عبر مسير الرواتب المعتاد.
- **لم يُمس:** المستقبل القديم `/api/public/hr/attendance` وأجهزته الثمانية وسجلاته، حضور الجوال ومواقع المدارس.

## الاختبارات
- `bunx vitest run src/lib/adms` — **12/12**: تطابق HMAC مع node:crypto الخاص بالجسر، replay، الوقت القديم/المستقبلي، تغيير body/path/query/method/key، عزل المؤسسات، تعارض الحمولة، نتيجة لكل حركة، PIN بأصفار، حدود 100 و256KB، الإغلاق الافتراضي، فشل الحفظ، صفحات المزامنة والاستئناف.
- `ADMS_TEST_DB_URL=postgres://postgres@127.0.0.1:55432/postgres BRIDGE_SRC=<bridge/service> NODE_PATH=node_modules bun scripts/adms-v1-isolated.ts` — **53/53** على Postgres محلي مؤقت (ليس قاعدة المشروع) بأسرار اصطناعية، منها **5 فحوص مشتركة مع كود الجسر الحقيقي** (Store + Worker + API القراءة الموقّع من حزمة التسليم 2.0.0): مزامنة موقّعة، عدم ظهور مكتب البواخر، تسليم حركتين بإيصالات دائمة، فقد الإقرار بعد COMMIT ← retry بالمعرف نفسه ← delivered بالإيصال نفسه دون صف ثانٍ.
- المعاينة: المسار يرد 503 `intake_disabled` على POST و405 على GET. لم يُرسل أي طلب إلى الجسر الحي أو قاعدة الإنتاج.

## الأسرار المطلوبة لاحقًا (لا تُرسل في المحادثة)
تُضاف كأسرار خادمية في المشروع عند قرار التفعيل:
- `ADMS_REGISTRY_KEYS` — مصفوفة JSON لكل مؤسسة: `rikaz_org_id`, `bridge_org_id`, `base_url` (`https://attendance.kalmalki.com`), `key_id`, `secret` (≥32).
- `ADMS_INGEST_KEYS` — مصفوفة JSON: `key_id`, `secret`, `bridge_org_id`, `rikaz_org_id`, `scope: "events:ingest"`, `enabled`, واختياريًا `not_before`/`expires_at` (يسمح بمفتاحين أثناء التدوير).
- `ADMS_EVENTS_INTAKE=enabled` — يفتح المستقبل. بدونه 503.

## اختلافات/نقاط تحتاج اتفاقًا مع العقد
1. المسار خارج `/api/public/`؛ يعمل لأن الموقع المنشور عام. إن قُيّدت رؤية الموقع لاحقًا سيُحجب المسار.
2. يجب نجاح مزامنة واحدة قبل أي تسليم؛ قبلها كل حركة `rejected/scope_or_mapping_requires_review` (الجسر يضعها review).
3. جهاز لم يُزامن بعد: الحركة تُقبل خامًا بحالة `device_unknown` ولا تُعالج حتى يظهر الجهاز.
4. وقت خارج السياسة (>10 د مستقبلًا أو >60 يومًا) يُقبل خامًا بحالة `time_review` ولا يُعالج.
5. event_id مكرر داخل الدفعة نفسها ← 422 للدفعة كلها؛ حركة بلا event_id صالح ← 422.
6. أثناء الإغلاق يرد 503؛ الجسر سيعيد المحاولة حتى 12 ثم review — لذا يبقى تسليم الجسر متوقفًا حتى التفعيل هنا.
7. لا مزامنة دورية تلقائية بعد (زر يدوي فقط).

1. تشغيل `scripts/adms-v1-isolated.ts` محليًا مع `BRIDGE_SRC` يشير إلى `bridge/service` (Node 22 لـ node:sqlite) وPostgres محلي مؤقت.

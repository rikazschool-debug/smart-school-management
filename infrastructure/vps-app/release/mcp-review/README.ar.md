# تعديل MCP المقترح — ينتظر مراجعة المالك

لم يُطبق SQL أو patch هنا على الإنتاج. ليست هذه الملفات ضمن `supabase/migrations`، ولا يطبقها مشغّل التثبيت أو النشر على هدف حي. يجوز لاختبارات CI تشغيل المقترح في العزل فقط.

الهدف إبقاء الاتصال وعنوانه وسرّه الحاليين للفحص، مع جعل تطبيق تغييرات الإنتاج من مسار الإصدار المعتمد وحده.

| الموضع | الحالي | المقترح |
|---|---|---|
| أدوات البوابة | ست أدوات، بينها execute_sql وapply_migration | أربع أدوات metadata؛ تُحجب الأداتان الحرتان |
| إنشاء كائنات public | مسموح للدور | سحب CREATE من هذا الدور فقط |
| عرض سجل الترحيلات | يفشل بخطأ 42501 | USAGE على المخطط، وSELECT على version وname فقط |
| قراءة SQL المحفوظ أو بيانات المدارس | لا تمنحها هذه الخطة | تبقى غير ممنوحة |
| صلاحيات نظام السيرفر وعضويات postgres | غير ممنوحة | تبقى غير ممنوحة |

مصدر البوابة الحالي يصفي إعلان الأدوات واستدعاءها باستخدام ALLOWED نفسها؛ لذا حصرها يرفض استدعاء أداة كتابة حتى إن احتفظ Lovable بنسخة قديمة من القائمة. تُختبر هذه الخاصية في QA قبل أي تبديل. ينبغي إعادة التحقق من بصمة الملف الفعلي والصورة قبل تطبيق patch، وعدم استبدال إعدادات الاتصال أو قاعدة البيانات.

الأثر عليك: يستمر عرض الجداول والإضافات والترحيلات والمستشارين. طلب SQL حر أو تنفيذ migration داخل محادثة Lovable لن يعمل على الإنتاج. اطلب من Lovable حفظ المقترح كملف Git واختباره بالسحابة، ثم اعتمد الإصدار من GitHub.

تنفيذ التعديل، إن وافقت عليه لاحقًا، عملية bootstrap منفصلة موثقة وبنسخة رجوع؛ لا ينفذ ثم يعاد داخل إصدار التطبيق. يبقى علم `mcp_write_path_reviewed=false` وبوابة النشر مغلقة حتى استكمال القرار والاختبار.

حُجز الإصدار `20261114180000_mcp_metadata_only` كاستثناء VPS اختياري معروف في baseline: لا يُشترط وجوده الآن ولا يطبقه مسار التطبيق تلقائيًا. إذا أُقرّ لاحقًا، يُسجل SQL نفسه مرة واحدة في سجل Supabase القياسي بمعاملة محروسة وبصمته، ويقبل المدقق وجوده دون محاولة إرساله إلى السحابة أو إعادة تطبيقه. لا تُكتب علامة applied صورية أو يُصلح التاريخ يدويًا.

إذا احتجت SQL قراءة مخصصًا عبر MCP مستقبلًا، يُصمم له مسار catalog محدود مستقل للمراجعة؛ لا نعيد فتح SQL الحر أو نستعمل فحص الكلمات وحده كضمان.

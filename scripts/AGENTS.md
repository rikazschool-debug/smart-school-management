# scripts rules
- scripts/rls-e2e.ts is the end-to-end permission test (creates and deletes its own test users); run it after any RLS change: `NODE_PATH=node_modules bun scripts/rls-e2e.ts`.
- Demo schedule data: scripts/seed-demo-schedule.ts (run after seed-demo.ts).
- Test scripts clean up only through scripts/lib/test-run.ts (run-registered users+schools); never delete by school id alone.
- scripts/comm-e2e.ts is the communication permission test: `NODE_PATH=node_modules bun scripts/comm-e2e.ts`; run it with rls-e2e after any change to communication SQL.
- scripts/circ-org-e2e.ts tests org-wide circulars; scripts/cleanup-scope-e2e.ts tests that cleanup stays inside its run.
- scripts/cleanup-e2e.ts tests run_file_cleanup.
- scripts/xbranch-files-e2e.ts tests attachments in cross-branch groups.
- Every test that creates orgs ends with TestRun.purgeOrg(org) (refuses orgs with schools not registered by the run).
- scripts/perm4-e2e.ts: owner-only users/roles, group creation, dept-head scope, publisher label. scripts/cleanup-monitor-e2e.ts: monitor alerts/recovery on an isolated channel.
- scripts/comm-browser-fixture.ts setup|teardown: isolated org/users (cbx-) for communication browser journeys; always run teardown after.
- scripts/homework-e2e.ts: homework lifecycle/permissions (`NODE_PATH=node_modules bun scripts/homework-e2e.ts`).
- scripts/comm-roles-e2e.ts: per-role communication (subject groups, transfer/teacher change, group-creation matrix, student limits, circulars).
- scripts/homework2-e2e.ts: feedback files, template copy, late joiners, report export scope.
- scripts/hw-browser-fixture.ts setup|teardown: isolated homework data (hbx-) for browser journeys; always run teardown after.
- scripts/assignment-validity-e2e.ts: assignment start/end boundaries (future, ended-but-approved, ends today, end<start, open session, independent dept-head role) on isolated data.
- scripts/attendance-e2e.ts: attendance/gate/pickup/call permissions and lifecycle (104 checks; incl. delegation lockout/confirmation, attachments, branch compare). scripts/attendance-tick-e2e.ts: scheduled absence review with a controlled clock (`--cron` waits for a real pg_cron run). scripts/att-closure-fixture.ts setup|teardown: two-branch data (acx-) for closure browser journeys. scripts/att-browser-fixture.ts setup|teardown: isolated data (abx-) for attendance browser journeys; always run teardown after.
- scripts/grades-e2e.ts: legacy write flow (superseded; fails on writes by design). Archive + homework closure checks: scripts/hw-closure-e2e.ts (`NODE_PATH=node_modules bun scripts/hw-closure-e2e.ts`).
- scripts/grades-browser-fixture.ts setup|teardown: isolated grades data (gbx-) + import XLSX files in /tmp/browser/gb; always run teardown after.
- scripts/admin-e2e.ts: school administration forms/requests/tasks permissions and lifecycle (`NODE_PATH=node_modules bun scripts/admin-e2e.ts`).
- scripts/admin-browser-fixture.ts setup|teardown: isolated abm- data for admin browser journeys; scripts/admin-task-journey.py runs the full task cycle (13 checks).; scripts/admin-request-journey.py runs the full request cycle (23 checks). scripts/admin-export-journey.py checks exports (5 checks). scripts/admin-req-export-journey.py checks request exports (9 checks).
- scripts/admin2-e2e.ts: duties (suggest/publish/substitute/conflict alerts/isolation) + meetings/minutes/decisions/calendar (44 checks). scripts/admin2-browser-fixture.ts setup|teardown: isolated abd- data; scripts/admin-duty-meeting-journey.py runs the duty+meeting browser journey (24 checks); always run teardown after.
- scripts/meetings-live-e2e.ts: owner multi-branch meetings, invitee scope, virtual room access/moderation (33 checks). scripts/admin-gaps-e2e.ts: scoped reminders + old notification after request transfer. scripts/meet-browser-fixture.ts setup|teardown: isolated mbx- data for room journeys; always run teardown after.
- scripts/admin-rpc-scope-e2e.ts: wrong-role/other-org/bad-input pass over all duty/meeting/live RPCs; run after changing any adm_* permission check.
- scripts/timetable-e2e.ts: timetable package acceptance (29 checks: inputs, conflicts, loads, last-two, impossible case, generation+independent verify, pins/fill/doubles, cancel/stale, roles, publish/views/notifications, substitutes). `--keep` leaves the isolated ttx- data and writes /tmp/browser/tt/fixture.json for browser journeys; `--teardown` removes it. Publishing now requires complete weekly counts, so fixtures that publish must set courses.weekly_periods to what they place.
- scripts/scope-e2e.ts: staff scope (vice/supervisor scopes, principal-only setup/timetable, gate-only scanning, scoped tasks, meeting organizers); `--keep` writes /tmp/browser/scope/fixture.json, `--teardown` removes it.
- scripts/closure-e2e.ts: no-login teachers in loads but not in pools/circulars; staff names owner-only. scripts/meet-room3-journey.py: 3-account live room (needs meet-browser-fixture). scripts/accounts-templates-journey.py: blank templates (needs accounts-browser-fixture).
- scripts/people-e2e.ts: unified people picker (people_pick) pools/gates per purpose, multi-role dedupe, prefix search, filters, id-leak and forged-participant checks (30 checks).
- scripts/accounts-e2e.ts: automatic accounts (staged access, forced change, phone confirmation, existing-account linking, one guardian for siblings, code-send rules; 20 checks). scripts/accounts-browser-fixture.ts setup|teardown: isolated acb- data + synthetic XLSX in /tmp/browser/acc; always run teardown after.
- scripts/otp-live-test.ts setup|local|supabase|status|teardown --phone 9665…: live WhatsApp code test on one consenting number via an isolated marked test login (never touches real accounts); run teardown when done.
- scripts/support-e2e.ts: support tickets phase 1 (scopes, workflow, edits history, guardian child link, platform scope, files, org isolation; 17 checks).
- scripts/support2-e2e.ts: support phase 2 (assign, cross-branch transfer, info requests partial view, private/team notes, escalation to platform; 17 checks).
- scripts/support3-e2e.ts: support phase 3 (working-hour targets, overdue filter/alerts once, designated alert person, assignee filter, scoped KPIs; 14 checks).
- scripts/support4-e2e.ts: support closure (pause/resume, re-armed alerts, cross-branch info, private-note leaks, helper lockout; `--cron` waits for the real job). scripts/support-browser-fixture.ts setup|teardown: isolated sbx- data; support-journey.py (12 checks, 8 accounts) and support-export-journey.py (12 checks); always run teardown after.
- scripts/support-phone-journey.py: support screens at 390px for 6 roles (needs support-browser-fixture).
- scripts/perm5-e2e.ts: section availability + flexible permissions (templates, custom roles, deny wins, multi-role, no self-escalation, students excluded, suspension wins, isolation; 20 checks).
- scripts/pc-e2e.ts: procurement & custody (lifecycle, VAT, derived balances, separation of duties, limits, duplicates, corrections, refunds, parallel disbursement, suspension, isolation; 31 checks). scripts/pc-browser-fixture.ts setup|teardown: isolated pcb- data; always run teardown after.
- scripts/pc2-e2e.ts: procurement phase 4 (requests, top-ups, settlement/close, carry-over, transfers, form versions, alerts, reports/export scope; 19 checks). pc-browser-fixture.ts `setup --open` also creates a disbursed custody with one approved invoice.
- scripts/schools-e2e.ts: owner schools/branches (add/edit, suspend pauses accounts + blocks joining, last-branch guard, restore only paused, audit, isolation; 13 checks).
- scripts/perm6-e2e.ts: flexible school permissions (base equivalence, templates = role rules, grant/deny/branch/org scope, suspended branch, real gate RPC, isolation; 20 checks).
- scripts/pc-need-e2e.ts: purchase needs (principal need → officer, line-linked invoices, partial delivery, separation of duties, isolation; 12 checks). pc-browser-fixture now also creates a principal.
- scripts/pc-journey-e2e.ts: full procurement journey (need→officer, draft-blocked settlement, reviewer edit, per-invoice decisions, notifications, branch overview scope, zero-balance auto-close → archive; 8 checks).
- scripts/vc-e2e.ts: class virtual sessions (schedulers, host/join, enrollment loss, isolation from admin meetings, attendance timings, report scope, cancel/end; 9 checks).
- scripts/maint-roles-e2e.ts: maintenance/transport role templates, principal base rule, branch scope, operations-area suspension, revocation, isolation (12 checks).
- scripts/maint-e2e.ts: maintenance lifecycle — school + bus journeys, routing, clarify, reschedule, decline/reassign, concurrent claim, no self-approval, internal notes, reopen/cancel, bus out-of-service/inspection/return, files, isolation, suspension, notification dedupe (26 checks).
- scripts/maint-need-e2e.ts: maintenance → purchase need (team suggests items only, principal creates one live need, amounts principal/owner only, re-create after cancel, history; 8 checks).
- scripts/maint-alerts-e2e.ts: daily maintenance alerts (overdue once per due date, bus date/km, service-only tick, operations switch; 6 checks).
- scripts/staff-e2e.ts: owner-created staff logins (username uniqueness case-insensitive, forced first change, multi-role on one account, existing-account link without password change, reset re-lock, no password in logs, suspension; 23 checks).
- scripts/perm7-e2e.ts: permission tree save/preview (preview rolls back, atomic perm_apply, 4 roles on one account, withdrawing one role keeps grants from another, deny wins incl. direct RPC, section people once per section, no self-edit, server first-password gate, reset revokes sessions, no passwords in logs; 20 checks).
- scripts/bounds-e2e.ts: owner limits (no self-custody approval, org isolation, bound by platform finance/operations suspension) + branch suspension (open session, other branch intact, reactivation restores only branch-paused; 8 checks).
- scripts/pc-transfer-journey.py: custody handover browser journey (needs pc-browser-fixture setup --open; 8 checks).
- scripts/pc-carry-form-journey.py: carry-over (no double totals) + custom invoice field with form versions (needs pc-browser-fixture setup --open --carry; 9 checks).
